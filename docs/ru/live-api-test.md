# Проверка реального API

`live_api_test` — интерактивный расширенный пример для пользователей maxoxide, которые хотят проверить библиотеку на реальном MAX Bot API со своими учётными данными. Он дополняет проверки без обращения к платформе реальными сценариями авторизации, доставки обновлений, сообщений, загрузок, подписок и необязательного администрирования чатов.

Пример выполняет настоящие API-запросы. Используйте отдельного тестового бота, контролируемых пользователей и чаты, а также временные данные. Не запускайте необратимые сценарии на рабочем боте или в важном чате.

## Получение подходящей версии исходников

Cargo не запускает примеры зависимости из использующего её приложения. Запускайте этот пример из рабочей копии исходников maxoxide той же версии, которая используется приложением:

```bash
git clone https://github.com/mammothcoding/maxoxide.git
cd maxoxide
git checkout "v<version>"
cargo run --example live_api_test
```

Замените `<version>` на версию maxoxide из приложения; например, для версии `3.1.0` выполните `git checkout v3.1.0`. Чтобы проверить ещё не выпущенный код из основной ветки, пропустите `git checkout`.

Требуется Rust 1.85 или новее.

## Учётные данные

Токен Bot API обязателен, секрет webhook необязателен:

- `MAX_BOT_TOKEN` — токен отдельного тестового бота;
- `MAX_WEBHOOK_SECRET` — секрет проверяемой или временно отключаемой webhook-подписки.

Если переменная отсутствует, пример запрашивает значение интерактивно и маскирует ввод. Пустой ввод секрета webhook пропускает это необязательное значение. Секреты не принимаются через аргументы командной строки.

Для интерактивного запуска без токена в командной строке:

```bash
cargo run --example live_api_test
```

Если учётные данные передаются через окружение, загружайте их обычным защищённым способом, а не сохраняйте в сценарии оболочки или файле репозитория. После запуска удалите временные переменные.

## Конфигурация

При старте выберите русский или английский язык и способ получения обновлений:

- `long_polling` проверяет типизированный, raw и отфильтрованный polling. Активные webhook-подписки блокируют long polling, поэтому пример может временно удалить их и восстановить после завершения.
- `webhook` запускает минимальный локальный HTTP-сервер и принимает обновления от MAX. Публичный HTTPS URL должен вести на указанный локальный адрес прослушивания напрямую или через контролируемый reverse proxy или tunnel.

Остальные параметры необязательны, если они не нужны выбранному сценарию:

- URL бота, который будет показан при ручной активации личного чата;
- публичная ссылка канала для `get_chat_by_link`;
- ID поста канала для необязательного этапа комментариев;
- публичный webhook URL и его секрет;
- пути к локальным файлу, изображению, видео и аудио;
- задержка между API-запросами, по умолчанию 400 мс;
- тайм-аут polling, по умолчанию 5 секунд.

После начала этапа личного чата отправьте боту новое сообщение `/live`. Сообщение, отправленное до появления приглашения, будет проигнорировано при очистке накопившихся обновлений.

## Проверяемые сценарии

Пример проверяет или предлагает интерактивно проверить:

- авторизацию и информацию о боте;
- доставку обновлений через long polling или webhook;
- получение канала по публичной ссылке;
- обычные и Markdown-сообщения, структурированные сообщения и отключение предпросмотра ссылок с адресацией по `chat_id` и `user_id`;
- клавиатуры, callback- и message-кнопки, запросы контакта и геопозиции, `clipboard`, Mini App и chat-кнопки;
- получение, изменение и удаление сообщений;
- чтение комментариев и необязательное подтверждаемое создание, получение, изменение и удаление;
- URL загрузки, потоковую загрузку файлов и bytes, а также необязательные методы отправки изображений, видео и аудио;
- webhook-подписки и необязательную временную замену меню команд;
- необязательные групповые сценарии: метаданные, участники, администраторы, действия отправителя, закрепление сообщений, временная смена названия, выход и удаление.

Необязательные сценарии без нужных данных или ручного подтверждения получают статус `SKIP`. Итоговая сводка содержит все `PASS`, `FAIL` и `SKIP`; при наличии хотя бы одного `FAIL` процесс завершается с ненулевым кодом.

## Побочные эффекты и очистка

Пример запрашивает подтверждение перед необязательными и необратимыми действиями, но подтверждённые операции выполняются реально:

- создаются тестовые сообщения и загруженные вложения, часть из них может остаться в чатах;
- webhook-подписки могут быть удалены и созданы заново;
- меню команд бота может быть временно заменено;
- title группы может быть изменён и восстановлен;
- могут изменяться права администратора;
- при подтверждении проверки комментариев создаётся, изменяется и удаляется временный комментарий;
- `delete_chat` и `leave_chat` являются необратимыми операциями, которые maxoxide не может откатить;
- chat-кнопка может создать настоящий чат, после чего пример предложит удалить его, выйти или оставить без изменений.

Пример по возможности восстанавливает сохранённые команды, webhook-подписки и название чата, а также удаляет созданный им временный файл загрузки. Очистка выполняется по мере возможности: прерывание процесса, потеря сети, недостаточные права или ошибка API могут оставить состояние изменённым. После каждого запуска проверьте команды бота, webhook-подписки, созданные чаты, состав групп и тестовые сообщения.

MAX не возвращает секреты webhook из `get_subscriptions`. Если существующая подписка использует секрет, укажите соответствующий `MAX_WEBHOOK_SECRET` до согласия на её временное удаление; иначе гарантировать идентичное восстановление нельзя.

## Ограничения

- `Bot::add_members` и прежняя обратимая проверка удаления участника получают статус `SKIP`, потому что MAX удалил endpoint добавления участников 30 сентября 2026 года.
- Экспериментальная партнёрская интеграция Digital ID не входит в этот пример и требует отдельных учётных данных и onboarding-схем.
- Успешный прогон подтверждает только выбранные сценарии для конкретного бота, аккаунта, клиента и момента времени. Он не доказывает производительность и доступность в production или корректность обработчиков приложения.
- Считайте вывод диагностическими данными и проверяйте его перед публикацией. Не публикуйте учётные данные, персональные данные, идентификаторы чатов и параметры webhook.
